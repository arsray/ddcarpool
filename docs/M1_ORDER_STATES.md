## 1. 「我的订单」Tab 结构

### 1.1 规则

| 用户身份 | 「我的订单」页 Tab |
|----------|-------------------|
| **仅乘车人** | 1 个 Tab：**搭车单** |
| **仅车主** | 1 个 Tab：**车主订单**（见 1.3 合并方案） |
| **双身份** | 2 个 Tab：**搭车单** \| **车主订单**，**默认锚定当前 Profile 身份**（与「我的」页车主/乘车人模式一致） |

### 1.2 三个 Tab 是否累赘？

**结论：不推荐顶层 3 Tab**（搭车单 / 接受订单 / 发车单）。

| 方案 | 评价 |
|------|------|
| 3 Tab | 车主侧拆太细，订单量少时切换成本高，且「接受」与「发布」常同属车主一次出行 |
| **2 Tab（推荐）** | 按**身份**分：乘车人看搭车单，车主看合并后的车主订单 |
| 1 Tab 全员 | 双身份用户无法清晰切换视角 |

### 1.3 车主两种类型是否合并？

**结论：合并为 1 个「车主订单」Tab，用类型标签区分，不做两个顶层 Tab。**

列表每行增加 **类型角标**（二选一）：

| 角标 | 原称 | 说明 |
|------|------|------|
| **接受** | ~~我接的搭车单~~ → **接受订单** | 车主在广场主动接的乘车人搭车单（角标 **接单**） |
| **发布** | 发车单 | 车主发布的自身行程（匹配推荐后续集成） |

可选 Filter Chip（订单少，**非必须**）：`全部 | 接受 | 发布`，默认「全部」。

与全局 Filter 叠加顺序建议：`身份 Tab` → `类型 Chip（仅车主）` → `状态 Filter（全部/未完成/已完成/已关闭）`。

## 2. 列表 Filter（状态 · 四档 · 身份通用）

| Filter | 包含一级状态 |
|--------|----------------|
| **全部** | 所有 |
| **未完成** | 匹配中 + 待出发 + 行程中 |
| **已完成** | 已完成 |
| **已关闭** | 已关闭 |

## 3. 一级状态命名（按订单类型）

底层码与 Filter 对齐；**展示文案**按类型区分。

| 底层码 | 乘车人 · 搭车单 | 车主 · 接受订单 | 车主 · 发车单 |
|--------|----------------|----------------|--------------|
| `open` | **匹配中** | *(不进列表，广场接单前)* | **匹配中** |
| `matched_pre` | **待出发** | **待出发** | **待出发** |
| `matched_trip` | **行程中** | **行程中** | **行程中** |
| `completed` | **已完成** | **已完成** | **已完成** |
| `closed` | **已关闭** | **已关闭** | **已关闭** |

### 3.1 文案修正（相对初稿）

| 项 | 定稿 |
|----|------|
| 乘车人 open | ~~待接单~~ → **匹配中**（无论是否有推荐/浏览） |
| 车主发车单 open | ~~招募中~~ → **匹配中** |
| 停止招募 | **停止匹配** |
| 取消匹配 | 与 **取消搭车单** 相同（乘车人侧统一说「取消搭车单」） |
| 已完成二级 | **无** |
| 车主「我接的搭车单」 | 改名为 **接受订单**（列表角标「接受」） |
| 车主接受订单 · 已关闭 | 第三种关闭原因（行程未完成关闭）**暂不定义** |
| 车主接受订单 · 已完成/已关闭 | **无「再接一单」** |
| Chat | 已完成/已关闭仍可进 Chat **至次日失效**（细则 M4）；历史是否持久化 M4 定；当前 **入口占位** |

## 4. 二级状态（列表副文案）

| 一级 | 乘车人 · 搭车单 | 车主 · 接受订单 | 车主 · 发车单 |
|------|----------------|----------------|--------------|
| 匹配中 | *(无)* | — | *(无)*；推荐未做，详情仅占位「查看匹配推荐」 |
| 待出发 | `{车主昵称} · {N}人` | `{乘车人昵称} · {N}人` | `{乘车人昵称} · {N}人`（格式与乘车人一致） |
| 行程中 | 与乘车人逻辑类似（如 `{昵称} · 同行`） | 同左 | 同左 |
| 已完成 | *(无)* | *(无)* | *(无)* |
| 已关闭 | 见 4.1 | 见 4.2 | 见 4.3 |

### 4.1 乘车人 · 搭车单 · 已关闭二级

| 二级 | 说明 |
|------|------|
| 已取消 | 乘车人取消搭车单 |
| 超时未匹配 | 超时仍无车主接受 |
| 匹配后取消 | 待出发/行程中取消（文案仍可用「已取消」或「匹配后取消」，实现时二选一） |

### 4.2 车主 · 接受订单 · 已关闭二级

| 二级 | 说明 |
|------|------|
| 已取消接单 | 车主取消 |
| 对方已取消 | 乘车人取消 |
| ~~行程未完成关闭~~ | **暂不做** |

### 4.3 车主 · 发车单 · 已关闭二级

| 二级 | 说明 |
|------|------|
| 已停止匹配 | 车主「停止匹配」 |
| 超时无匹配 | 到点仍未接任何搭车单 |
| 已取消 | 车主取消发车单 |

## 5. 详情页操作按钮

### 5.1 乘车人 · 搭车单

| 一级 | 按钮（最多 2 个为主；匹配中维持 2 个） |
|------|----------------------------------------|
| 匹配中 | 编辑 \| 取消搭车单 |
| 待出发 | 进入 Chat \| 取消搭车单 |
| 行程中 | 进入 Chat |
| 已完成 | 进入 Chat（占位，次日失效规则 M4）\| 再来一单 |
| 已关闭 | 再来一单 |

### 5.2 车主 · 接受订单

| 一级 | 按钮 |
|------|------|
| 待出发 | 进入 Chat \| 取消匹配 |
| 行程中 | 进入 Chat |
| 已完成 | 进入 Chat（占位，次日失效 M4） |
| 已关闭 | *(无再接/再来)* |

### 5.3 车主 · 发车单（统一为车主行程）

| 一级 | 按钮 |
|------|------|
| 匹配中 | 查看匹配推荐(占位) / 编辑 / 停止匹配 |
| 待出发 | 进入 Chat \| 取消匹配（有关联发车单时弹窗，见 5.4） |
| 行程中 | 进入 Chat |
| 已完成 | 进入 Chat（占位）\| 再发一单（仅 publish 来源） |
| 已关闭 | 再发一单（仅 publish 来源） |

### 5.4 取消匹配弹窗（待出发 · 车主）

统一 `showModal`，标题 **取消匹配**，按钮 **取消匹配** / **取消**。

| 场景 | 内容 | 确认后 |
|------|------|--------|
| 有关联发布订单（`hasPublishTrip: true`） | 将取消与对方的同行匹配。您发布的车主订单将继续匹配。 | 解绑匹配；发布类车主订单回 **匹配中** |
| 纯接单（`hasPublishTrip: false`） | 将取消与对方的同行匹配。 | 解绑匹配 |

关闭发布订单仅通过 **停止匹配**（匹配中状态），不在此弹窗提供。

### 5.5 停止匹配弹窗（匹配中 · 发布类车主订单）

**内容：** 该车主订单将被关闭。  
**按钮：** 停止匹配 / **取消**（不做任何事）

### 5.6 车主订单来源 Tag

列表右上角、详情页展示 **发布** / **接单** 角标（`createdFrom: publish | accept`）。

## 6. 业务规则摘要

| 规则 | 说明 |
|------|------|
| 乘车人能力 | **仅可发布** 搭车单，**不可接单** |
| 车主能力 | 可 **发布** 车主订单（用于匹配锚点）+ **接单**（广场主动接或根据匹配推荐选择接） |
| 乘车人多单 | 可同时有多条 **匹配中** 搭车单 |
| 发布订单用途 | 发布仅为匹配推荐锚点；**不会自动匹配**，须车主主动选择接单 |
| 匹配完成 | 始终由 **车主接受搭车单** 完成 |
| Chat | 完成后可进 Chat 至 **次日失效**；历史存储 M4 定 |
