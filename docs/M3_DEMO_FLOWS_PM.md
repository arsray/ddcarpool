## 一、本 PR 覆盖的五种状态（英文存储码）

| 底层码 | UI 中文 | 本 PR 是否可演示 |
|--------|---------|------------------|
| `matching` | 匹配中 | ✅ 发单后、被接单前 |
| `pending_departure` | 待出发 | ✅ 车主接单后 |

## 二、乘车人 · 发单（Alice）

**入口：** 底部 Tab「发布」

```mermaid
flowchart LR
    A[填写日期/时间/路线/人数/备注] --> B[发布搭车单]
    B --> C[匹配中]
    C -->|车主接单| D[待出发]
    D -->|车主点完成| E[已完成]
    C -->|超时未接| F[已关闭]
```

**要点：**

- 仅 **乘车人身份** 可发布；纯车主需先添加乘车人身份  
- 发单成功后进入 **匹配中**，司机可在广场看到（自己发的单不会出现在自己的广场列表）  
- 被接单后，乘客在 **通知中心** 收到通知（含日期、时间窗、路线）  
- 本 PR **暂无** 乘车人侧「取消订单」按钮  

**Mock 账号：** Alice · `alice.passenger@disney.com`

## 三、车主 · 广场接单（Bob）

**入口：** 底部 Tab「广场」

```mermaid
flowchart LR
    A[浏览/筛选匹配中订单] --> B[确认接单]
    B --> C[待出发]
    C -->|详情页点完成| D[已完成]
```

**页面结构（自上而下）：**

1. 标题区「广场」+ 待办提示（有已接单时）  
2. **已接单 · 待出发**（可点进详情）  
3. **筛选条件**（日期含星期、时间、出发、到达）  
4. **匹配中** 订单列表（未筛选时按出发时间排序展示全部）  

**要点：**

- 接单后，该单从「匹配中」列表 **消失**，出现在顶部「已接单」  
- **同一订单不可重复接单**  
- 本 PR 简化：**无「出发」步骤**，送达后在详情页直接点 **「完成」**  
- 可同时接多单，已接单按出发时间排序  

**Mock 账号：** Bob · `bob.driver@disney.com`

## 四、与完整产品规划的差异（本 PR 故意简化）

| 规划（ORDER_FLOWS_PM） | 本 PR Mock |

| 车主「发布行程再匹配」 | 未做 |

## 六、建议验收路径（5 分钟）

1. Bob 登录 → 广场 → 筛选 → 接单  
2. 确认：匹配列表无该单；顶部出现已接单卡片  
3. 切 Alice → 通知中心 → 看到接单通知  
4. Bob → 已接单详情 → 「完成」  
5. Alice → 发布 → 填写表单 → 发布成功
