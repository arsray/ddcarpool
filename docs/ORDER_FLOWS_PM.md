## 一、五种订单状态（两种身份通用）

| 状态 | 用户理解 |
|------|----------|
| **匹配中** | 还在等人接 / 还在等匹配 |
| **待出发** | 已经配上，还没出发 |
| **行程中** | 已在路上 |
| **已完成** | 正常结束 |
| **已关闭** | 取消、停止匹配、超时等 |

---

## 二、乘车人 · 搭车单

**谁能做：** 乘车人 **只能发布** 搭车单，**不能接单**。

```mermaid
flowchart LR
    A[发布搭车单] --> B[匹配中]
    B -->|车主接单| C[待出发]
    B -->|自己取消 / 超时| F[已关闭]
    C -->|到出发时间| D[行程中]
    C -->|取消| F
    D -->|行程结束| E[已完成]
    D -->|取消| F
```

**要点：**

- 可以同时有多条「匹配中」搭车单  
- **必须等车主主动接单**，不会自动配上  
- 配上后：乘车人看到「车主 xxx 已接单」

---

## 三、车主 · 两种发单方式

车主有两个入口，**合并显示在「车主订单」里**，用角标区分：

| 角标 | 含义 |
|------|------|
| **接单** | 在广场看到搭车单，主动接的（主流程） |
| **发布** | 自己先发一条行程，等系统推荐后再选接哪单 |

---

### 3.1 车主 · 接单（广场主动接）

**特点：接完直接进入「待出发」，没有「匹配中」。**

```mermaid
flowchart LR
    A[在广场选一条搭车单] --> B[待出发]
    B -->|到出发时间| C[行程中]
    B -->|取消匹配| F[已关闭]
    C -->|行程结束| D[已完成]
    C -->|取消| F
```

**要点：**

- 和乘车人那条搭车单 **成对出现**  
- 取消后：乘车人搭车单回到「匹配中」

---

### 3.2 车主 · 发布（先发行程，再选接哪单）

**特点：发完先「匹配中」，接单后才「待出发」。**

```mermaid
flowchart LR
    A[发布车主行程] --> B[匹配中]
    B -->|看推荐 / 去广场| B
    B -->|选中一条并接单| C[待出发]
    B -->|停止匹配 / 超时| F[已关闭]
    C -->|到出发时间| D[行程中]
    C -->|取消匹配| G[发布单回匹配中]
    G --> B
    C -->|仅纯接单场景| F2[已关闭]
    D -->|行程结束| E[已完成]
    D -->|取消| F2
```

**要点：**

- 发布 **不会自动匹配**，只是「锚点 + 推荐用」  
- **取消匹配**（待出发时）：和对方的配对解除；**发布单回到匹配中**（不是整单关闭）  
- **停止匹配**（还在匹配中时）：整条发布单 **已关闭**

## 四、一次匹配 = 两个人各看各的订单

```mermaid
sequenceDiagram
    participant 乘车人
    participant 系统
    participant 车主

    乘车人->>系统: 发布搭车单（匹配中）
    车主->>系统: 在广场或推荐里选这条，点接单
    系统->>乘车人: 待出发 · 车主 xxx 已接单
    系统->>车主: 待出发 · 乘客 xxx N 人
    Note over 乘车人,车主: 之后一起：待出发 → 行程中 → 已完成
```
